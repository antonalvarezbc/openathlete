OpenAthlete is designed to be self-hosted, giving you full control over your data and privacy.

## Docker Compose (recommended)

Requirements: a server with `git`, `docker` and the `docker compose` plugin.

1. Clone the repository:

```bash
git clone https://github.com/openathleteorg/openathlete.git
cd openathlete
```

2. Create your configuration. `docker compose` reads the `.env` file at the repository root:

```bash
cp .env.example .env
```

3. Fill in the two required secrets, each with its own random value:

```bash
openssl rand -base64 48   # paste as JWT_SECRET_KEY
openssl rand -base64 48   # paste as HASH_PEPPER
```

4. Set the public URLs if you are not running on `localhost`:

```properties
APP_URL=https://openathlete.example.org          # where users open the app
API_PUBLIC_URL=https://api.openathlete.example.org # where browsers reach the API
CORS_ORIGINS=https://openathlete.example.org
```

5. Start the stack:

```bash
docker compose up -d --build
```

The web app listens on port 80 and the API on port 3000 (change them with `WEB_PORT` and `API_PORT`). PostgreSQL and Redis are only reachable from the server itself.

Database migrations run automatically when the API starts. The first account you create is a regular account; there is no default admin.

### Prebuilt images

Each release publishes multi-architecture images (amd64 and arm64) to GitHub Container Registry:

- `ghcr.io/openathleteorg/openathlete-api`
- `ghcr.io/openathleteorg/openathlete-web`

They take the same variables as the Compose setup; the web image reads `API_PUBLIC_URL` when it starts. Pin a version tag (for example `1.2.3` or `1.2`) rather than `latest` to control upgrades.

### Optional features

Leave a variable empty to disable the feature:

| Feature | Variables |
| --- | --- |
| AI session generation and feedback | `OPENAI_API_KEY` |
| Transactional email (password reset, invitations) | `BREVO_API_KEY`, `BREVO_FROM_EMAIL` |
| Device sync | `STRAVA_*`, `GARMIN_*`, `POLAR_*`, `SUUNTO_*` |
| AI load estimation of planned sessions | `ENABLE_TRAINING_LOAD_ESTIMATION` (with `OPENAI_API_KEY`) |
| Billing | `STRIPE_*` (not needed for self-hosting) |

Every API variable is documented in `apps/api/.env.example`.

Activities from connected devices, including historical imports, are fetched by background jobs that run inside the API container (`ENABLE_ACTIVITY_IMPORT` and `ENABLE_ACTIVITY_PROCESSING`, both on by default). To run them in a separate worker instead, start a second API container with these two variables set to `true` and `SKIP_MIGRATIONS=true`, and set them to `false` on the API.

### HTTPS and reverse proxies

Put the web app and the API behind a TLS-terminating reverse proxy (Caddy, Traefik, nginx, Coolify). The API trusts `X-Forwarded-For` only from proxies on private networks, which covers a proxy on the same host or Docker network. If another public proxy sits in front (for example Cloudflare), set `TRUST_PROXY` to the number of proxy hops so rate limiting sees real client IPs.

### Updating

```bash
git pull
docker compose up -d --build
```

<Callout type="warn">
**Upgrading an instance started before October 2026:** `JWT_SECRET_KEY` and `HASH_PEPPER` used to have built-in defaults and are now required.

- Set a new random `JWT_SECRET_KEY`. The API refuses to start with the former default, which was public. Users are simply logged out.
- Keep `HASH_PEPPER=dev-pepper-change-in-production-min-32-chars` if your instance used the default. Changing the pepper invalidates every existing password.
</Callout>

## Manual deployment

### API (NestJS)

```bash
pnpm install
pnpm database run db:generate
pnpm shared build
pnpm api build
pnpm database run db:deploy   # apply migrations
```

Configure the API with the variables from `apps/api/.env.example` (at least `DATABASE_URL`, `JWT_SECRET_KEY`, `HASH_PEPPER`, `ENV` and `NODE_ENV`), then start it with `pnpm api start:prod`.

### Web app (React + Vite)

```bash
VITE_API_BASE_URL=https://api.your-domain.com pnpm web build
```

Serve `apps/web/dist` with any static web server, falling back to `index.html` for client-side routes:

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /path/to/apps/web/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

## Backups

Back up the PostgreSQL database regularly, for example with `pg_dump`, and keep your `.env` somewhere safe: losing `HASH_PEPPER` means no existing password can be verified.

## Troubleshooting

**The API container keeps restarting.** Run `docker compose logs api`: the API lists every invalid or missing variable at startup.

**CORS errors in the browser.** `CORS_ORIGINS` must contain the exact URL users open, including the scheme and port.

**Links in emails point to the wrong host.** Set `APP_URL` to the public URL of the web app.

**The web app calls the wrong API URL.** Check `API_PUBLIC_URL`, then restart the web container: `docker compose up -d web`.
